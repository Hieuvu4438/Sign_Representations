# H004 — Adaptive query window acquisition for fixed dictionary retrieval

Status: candidate, one registered CPU feasibility diagnostic H004_v0; no scientific
pilot or GPU allocation. Owner Codex. [D021](../decisions/D021.md).

Question: can an expensive frozen encoder acquire fewer native windows per query
while preserving a specified dictionary decision with a justified stopping rule?
The user benefit sought is predictable query cost/quality, not a novel stride.
Full-clip native timestamps and fixed train gallery remain offline inputs.

Potential mechanism: bound the unobserved contribution to activity-weighted
query scores, then continue acquiring windows when competitor classes remain
possible. Fixed dictionary vectors and labels are allowed; query labels are not
used for acquisition. Deterministic completion envelopes are tested first; a
probabilistic candidate would need its own anytime-valid risk and finite-population
assumptions, not a softmax confidence heuristic.

Falsifier: valid bounds require almost all windows; control bookkeeping/decode
eliminates actual savings; fixed uniform sampling dominates at matched decision
fidelity/cost; or the alleged mechanism is only known adaptive MIPS under a new
task name. Best-arm sampling and confidence sequences are prior art. No method
novelty or successful risk control established.

Diagnostic uses unchanged COHORT002/VID003/CACHE006, fixed100-class/one-example
three galleries, all383 dev queries. Data have previously been used for H002 dev,
so this is exploratory. Native16-frame/stride2 feature producer and activity
aggregation retained. No P004 test access or rescue of its10-frame input failure.
Budget one formula, one seed1701 order,180s CPU/0GPU. Primary gate and caveats in
D021. Preserve all pairs and failures; no seed/threshold/bound fitting.

Scale only if the feasibility gate passes, the exact numerical/metric contract
and closest-work difference are credible, and GPU allocation is explicitly
registered within the unchanged total budget. A Top1 certificate does not satisfy
H002's DCG endpoint. Strong later controls would include dense, fixed uniform,
matched-budget random and a confidence-margin escalation heuristic under identical
dictionary/input/context access. No method implementation promoted for paper.
