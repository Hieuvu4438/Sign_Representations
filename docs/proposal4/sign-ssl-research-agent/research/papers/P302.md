## Mechanism

Not a model. Relevant mechanism for this project: features are type-level labels attached to each gloss; any probe on ASL Citizen tokens inherits the label of the gloss, so a model that identifies the gloss trivially knows its features (see Critical analysis).

## LOCAL_AUDIT: join to ASL Citizen

- Join key: ASL Citizen CSV column `ASL-LEX Code` ↔ ASL-LEX `Code` column (format `A_03_054`; ASL-LEX 2.0 defines this as section/batch position code; it also has `EntryID`, `LemmaID`). Example: APPLE → `A_03_054` → EntryID `apple`, Handshape.2.0 `bent_1`, SelectedFingers `i`, Flexion `Bent`, SignType `OneHanded`, Movement `None`, RepeatedMovement 1, MajorLocation `Head`, MinorLocation `CheekNose`, Contact 1.
- Coverage: 2,723 distinct codes in ASL Citizen = 2,722 real codes + literal `NA`. 2,722/2,722 real codes match an ASL-LEX row. Glosses joinable: 2,725 / 2,731. Videos joinable: 83,216 / 83,399. Unjoinable (code `NA`): ABOVE (31 videos), INSTINCT (30), LETTER2 (31), MINIMUM1 (30), SENTENCE1 (30), WELCOME1 (31) — 183 videos.
- Many-to-one: WHATFOR1/WHATFOR2/WHATFOR3 → `C_02_054`; RESEARCH1/RESEARCH2 → `B_03_084` (distinct ASL Citizen classes with identical ASL-LEX phonology row). No gloss maps to >1 code.
- Phonology columns available (primary morpheme): `Handshape.2.0, MarkedHandshape.2.0, SelectedFingers.2.0, Flexion.2.0, FlexionChange.2.0, Spread.2.0, SpreadChange.2.0, ThumbPosition.2.0, ThumbContact.2.0, SignType.2.0, Movement.2.0, RepeatedMovement.2.0, MajorLocation.2.0, MinorLocation.2.0, SecondMinorLocation.2.0, Contact.2.0, NonDominantHandshape.2.0, UlnarRotation.2.0`; repeated for morphemes M2–M6 (compounds); plus per-feature frequency columns, `Neighborhood Density 2.0`, `Parameter.Neighborhood.Density.2.0`, `PhonotacticProbability`, `Phonological Complexity`, `SignFrequency(*)`, `Iconicity(*)`, `LexicalClass`, `Compound.2.0`, `Initialized.2.0`, `FingerspelledLoanSign.2.0`, SignBank IDs, AoA. ## Critical analysis

- INFERENCE (important): on ASL Citizen, every test gloss is a training gloss, so a "phonology probe" trained on token features with type-level labels can be solved by gloss identification + lookup. Its accuracy is bounded below by majority rates (above) and approximately ≥ Rec@1 + (1−Rec@1)·P(feature shared | wrong gloss). To diagnose what a frozen representation encodes *about phonology itself*, the probe must be trained and tested on disjoint gloss sets (gloss-disjoint split, e.g., stratified so each feature value occurs in both), and reported relative to majority and to a "gloss-identity" control. P312 used exactly this idea (retraining excluding minimal-pair signs).
- Coding is from one citation-form reference video; ASL Citizen tokens may realize variants (handshape assimilation, one- vs two-handed variants). Label noise per token is UNKNOWN.

- Column semantics CONFIRMED from `signdataKEY.csv` (streamed 2026-10-05): `UlnarRotation.2.0` = "Wrist Twist" ("Whether or not the wrist twists"); `Movement.2.0` = "Path Movement" of the first morpheme; `Handshape.2.0` = "unique combination of selected fingers, flexion, spread, thumb position, and thumb contact"; `Flexion.2.0` = aperture at sign onset; `MinorLocation.2.0` = dominant-hand location at sign onset; `SignType.2.0` = Battison sign types; `RepeatedMovement.2.0` covers path, wrist twist or handshape change repeating; all features describe the INITIAL morpheme (M2–M6 columns for later morphemes). Key file describes `Code` as "A code that uniquely identifies each video in the database".
