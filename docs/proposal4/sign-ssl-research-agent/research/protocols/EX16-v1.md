# EX16-v1 — SignRep reproduction vs JEPA with identical SignRep sign priors (user request 2026-10-08)

## Status

LOCKED 2026-10-08 ~19:20 +07 before any EX16 training run. Validation-only (ASL Citizen val); no test split.

## Audit of the reproduction (`method/jepa_baseline`, Codex) against the paper (arXiv 2503.08529v1 §3–5, §7.2, A1–A4)

Matches: 9 priors from the real 3-D teacher (61 kpts, FK with corpus-median bones, Euler angles as sin/cos, signed xyz distances with the A1 indices, confidence > 0.5); sign decoder = authors' ProjectionModel on z_avg = fc(LN(mean tokens)); smooth-L1 recon with Table 9 weights/scales; variance (sum over D, hinge 1, w 1.0) and covariance (1/N, off-diagonal², w 0.004); adversarial Eq. 7–9 gated by E_M > E_U (w 2.0); discriminator per A4 (style ×100, 2-layer MLP + LN, 4-layer spectral-norm MLP, BCE, Adam .5/.9 wd 1e-3, EMA 0.1); Hiera-B Kinetics-MAE init, 80% mask units, AdamW .9/.95 wd .5, layer decay .85, clip 1; two 16-frame views per video. Declared unknowns (not in paper): augmentation probabilities, Gram normalisation. Data limitation: the activity prior is almost never labelled on ASL Citizen (reference torso keypoints rarely observed; Codex POSE_PRIORS_AUDIT.md: 0.115% coverage). No code change was required for fidelity; one resume bug fixed (`batch=None`, logged in ASLC002 launch log).

## Design (only the paradigm differs)

- Data: ASLC002 corpus — 3,000 unlabelled ASL Citizen train videos (300 classes × 10) with 3-D teacher pose (40k-video extraction would need ≈ 85–170 h CPU; user approved the subset 2026-10-08).
- Shared: prior targets/masks and decoder (reproduction code), prior loss (Table 9), augmentation recipe (same functions/probabilities, executed on GPU; worker resizes the signer crop to 256 with OpenCV area/bilinear instead of torchvision antialias — declared numerical deviation), optimiser recipe, batch 32 views (16 videos × 2), 4,000 steps, 10% warm-up, cosine, bf16, seed 20261008.
- Run order (user 2026-10-08, before any EX16 run): SR3D → JV3D → evaluation → JH3D. Primary comparison for the user: JV3D vs SR3D; JH3D vs SR3D is the paradigm-only control.
- Arms:
  - **SR3D** — SignRep reproduction: priors + var/cov + adversarial (Pretrainer of the reproduction).
  - **JH3D** — JEPA on the *same* Hiera-B Kinetics-MAE init and 80% random mask units: priors + latent prediction (L1 to layer-normed EMA-teacher final tokens at masked units, EMA 0.99925; predictor 6 × 384 transformer, weight 1.0). No var/cov/adversarial.
  - **JV3D** — JEPA on V-JEPA 2.1 ViT-B (official encoder/predictor body, multi-block masks, 2.1 context loss) + the same prior decoder/loss.
- Extra reference: Codex ASLC002 final model (SignRep reproduction, batch 4 views, 5,000 steps).

## Evaluation (`jt/evaluate.py`, as EX15-v1.2)

Feature = z_avg (fc of mean tokens) per 16-frame window, stride 8; primary LOSO R@1 with whitened-512 readout on ASL Citizen val; probes; signer probe; geometry. Primary weights = online model (SignRep has no EMA); EMA weights reported for JEPA arms.

## Decision

- Primary question: JH3D vs SR3D (paradigm only). "JEPA better" if JH3D − SR3D ≥ +1.0 R@1 with signer-cluster CI > 0; "SignRep better" if ≤ −1.0 with CI < 0; otherwise no clear difference. Secondary: JV3D vs SR3D (paradigm + init). Single seed (screening); a positive primary result is repeated with 2 more seeds before any paper statement.
