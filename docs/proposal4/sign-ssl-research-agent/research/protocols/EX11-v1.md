# EX11-v1 — Pilot H007: 32-frame SignRep student that must encode the ordered halves of a sign

## Status

LOCKED 2026-10-06 before any H007 training (smoke test only: strict load, finite outputs, untrained student32 ≈ teacher on duplicated windows, cos 0.993).

## Hypothesis (H007)

SignRep's 16-frame window is a stated limitation (v1 App. A8). The order-aware readout gain (C012) shows the order of two halves of the active span is informative. If one 32-frame window embedding is trained (label-free) to linearly contain the frozen teacher's embeddings of its first and second halves *in order*, then the encoder itself carries the order information and the **plain averaged readout** of 32-frame windows should approach what bins2 achieves on the original encoder.

Last step evaluated.

## Evaluation (validation only)

val windows of 32 frames at stride 4 (clips < 32 frames padded), student `features`; readout R0 = activity-weighted mean with γ32(t) = max(γ(t), γ(t+16)) from the original model's activity cache; R1 = bins2 on the same windows (active span, γ ≥ 0.5). Leave-one-signer-out inside val; paired signer bootstrap.

## Decision rules

- H7 supported (pilot) if H7-R0 − C7-R0 ≥ +1.0 R@1 (CI > 0) **and** H7-R0 ≥ B0-R1 − 1.0 (the encoder recovers most of the readout gain on its own).
- Refuted if H7-R0 − C7-R0 ≤ 0.
- Report also R1 for all arms (does the encoder change add on top of the better readout?).
